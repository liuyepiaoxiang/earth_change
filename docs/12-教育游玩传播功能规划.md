# 未来地球引擎：教育、游玩与传播功能规划

> 版本：1.0  
> 日期：2026-10-18  
> 阶段：产品功能规划与交互设计，不包含本轮代码实现  
> 目标：让用户在理解模型的同时，愿意实验、重复探索并分享自己的发现  
> 设计定位：**一台可以亲手实验的未来地球课堂**

---

## 1. 产品定位

未来地球引擎不是单纯的气候数据仪表盘，也不是用灾难数字制造刺激的小游戏。

它应该成为一个让用户完成以下过程的交互产品：

```text
提出一个未来问题
  → 先做出判断
  → 调整一条路径
  → 运行模拟
  → 观察结果变化
  → 理解变化原因
  → 反思模型边界
  → 分享一个有上下文的发现
```

产品对外的核心表达：

> **选择一条未来路径，亲手改变几个条件，看看地球、城市和海岸会怎样变化。**

教育意义来自因果理解，游玩感来自实验和任务，传播性来自用户自己的结果和故事。

---

## 2. 三个产品目标

### 2.1 教育目标：让用户理解因果，而不是记住数字

用户完成一次实验后，至少能够解释：

- 排放为什么会改变 CO₂。
- CO₂ 为什么会改变辐射强迫。
- 海洋为什么会延缓升温，但不能永久消除升温。
- 海平面为什么具有长期滞后。
- 全球平均温度为什么不等于每个城市的实际天气。
- 模型中的动态耦合、诊断估计和城市降尺度有什么区别。
- 参数不确定性区间和完整科学共识区间不是同一个概念。

### 2.2 游玩目标：让用户愿意再做一次实验

用户应该可以持续发现新的问题：

- 如果减排提前 15 年，会发生什么？
- 哪个情景最早超过 2°C？
- 哪些城市最早接近海平面阈值？
- 海平面上升主要来自热膨胀还是冰冻圈？
- 植被和冻土反馈会改变多少结果？
- 如果气候状态相同，只改变海岸防护，结果有什么不同？

### 2.3 传播目标：让用户分享“我的发现”

分享内容不能只有一个脱离语境的数字，而应该包含：

- 情景。
- 年份。
- 城市或区域。
- 关键指标。
- 与另一个情景的差异。
- 模型性质和适用边界。
- 可复现链接。

## 3. 设计原则

### 3.1 先问题，后数据

产品入口不直接问“请选择 SSP”，而是先问：

> 你想探索哪个问题？

例如：

- 2100 年四种未来有什么差异？
- 我的城市会怎样？
- 提前减排能改变多少结果？
- 海平面上升主要来自哪里？
- 2500 年的长期变化会怎样？

### 3.2 先预测，后揭示

关键指标先让用户猜，再运行模拟。结果出来后显示：

```text
你的判断
模型结果
差异大小
为什么会这样
```

### 3.3 每次操作都回答三个问题

用户修改一个条件后，系统应说明：

1. **发生了什么？**
2. **为什么会这样？**
3. **这意味着什么？**

### 3.4 奖励理解，不奖励灾难

不设置“最惨未来排行榜”，不鼓励用户制造最高温度、最多淹没城市或最大损害。

奖励应该来自：

- 完成一个实验。
- 正确理解一个因果关系。
- 能区分全球量和局地量。
- 能解释模型边界。
- 完成多个情景的比较。
- 分享一个有上下文的发现。

### 3.5 简单解释和技术解释分层

默认内容用普通语言表达；用户点击“为什么”或“技术细节”后，再展示公式、方程 ID、参数和数据源。

### 3.6 科学边界始终可见

所有结果都应携带：

- 单位。
- 年份。
- 情景。
- 模型层级。
- 数据来源。
- 适用范围。
- 不确定性或长期外推提示。

## 4. 用户分层

| 用户 | 目标 | 推荐入口 | 主要功能 |
|---|---|---|---|
| 第一次访问者 | 先理解产品是什么 | `/overview` | 导览、演示、简单任务 |
| 普通探索者 | 看自己关心的未来 | `/` | 地球、情景、时间轴、城市 |

| 内容传播者 | 生成可分享的发现 | 分享模式 | 分享卡、URL、Embed、PNG |
| 开发者/研究用户 | 核对模型事实源 | 完整规格索引 | 方程、参数、数据、版本指纹 |

## 5. 产品模式

产品不应该让所有用户进入同一套复杂界面。建议提供六种模式。

### 5.1 导览模式：3–5 分钟看懂模型

入口：Overview 的“先看懂模型”。

流程：

```text
提出问题
  → 选择一个答案
  → 运行简化实验
  → 看模型结果
  → 阅读原因解释
  → 完成一句话复述
```

示例主题：

- 为什么海洋会延缓升温？
- 为什么海平面不会随着减排立即停止上升？
- 全球升温和城市升温有什么关系？
- 诊断式结果和动态耦合结果有什么区别？

### 5.2 探索模式：当前 Dashboard

保留现有 Dashboard，作为自由探索空间：

- 情景选择。
- 时间轴。
- 3D 地球。
- 图层控制。
- 城市点选。
- 分析抽屉。
- 不确定性开关。
- 里程碑时间线。

需要增加一个入口提示：

> 现在你正在查看一条完整情景路径。想自己改变排放和减排年份，可以进入实验室。

### 5.3 实验室模式：改变未来条件

复用现有 `ExperimentEditor`，扩展成用户可以理解的实验控制台。

第一版允许调整：

| 控制项 | 用户看到的名称 | 可选范围 | 影响 |
|---|---|---|---|
| 排放强度 | 排放规模 | 0.5–1.5 倍基准路径 | CO₂、温度、海平面 |
| 减排起始年 | 什么时候开始减排 | 2025–2100 | 累计排放和峰值 |
| 净零年份 | 什么时候接近净零 | 2030–2200 | 长期 CO₂ 路径 |
| 甲烷路径 | 甲烷排放路径 | 低/中/高 | 非 CO₂ 强迫 |
| 碳汇能力 | 陆地碳汇 | 保守/基准/增强 | CO₂ 和温度 |
| 海岸防护 | 适应程度 | 无/中等/高 | 城市暴露结果 |

每个控制项旁边必须有一个“为什么”解释：

```text
减排起始年越晚 → 累计排放越高 → CO₂ 峰值更高 → 温度和海平面差异更大。
```

### 5.4 挑战模式：带目标的情景任务

挑战不是考试，也不是简单积分，而是带目标的实验任务。

示例：

- 让 2100 年全球升温低于 2°C。
- 找出四种 SSP 中最早超过 1.5°C 的情景。
- 找出海平面上升中贡献最大的分量。
- 在不改变基础气候状态的前提下，减少城市暴露人口。
- 比较“提前减排”和“增强适应”的差异。
- 判断哪些结果属于动态耦合，哪些属于诊断估计。
- 找到 2500 年后仍然存在明显长期滞后的变量。

### 5.5 故事模式：一条未来时间线

复用现有 `MilestoneFeed`，把时间线做成“未来纪录片”：

- 2030：近未来变化开始显现。
- 2050：情景差异变得明显。
- 2100：主要情景对照点。
- 2200：长期海平面继续累积。
- 2500：探索性长期外推。

用户点击事件后看到：

- 事件触发变量。
- 相关模型层级。
- 当前年份数值。
- 为什么值得注意。
- 这是不是预测、诊断或影响函数。

### 5.6 分享模式：把实验变成一个故事

复用现有 `SharePanel`，扩展为：

- 当前结果分享。
- A/B 情景差异分享。
- 城市故事分享。
- 挑战完成分享。
- 时间线事件分享。
- Embed 模式。

## 6. 教育功能体系

### 6.1 预测卡

每个导览任务先显示一个预测问题。

示例：

```text
问题：SSP2-4.5 在 2100 年的全球升温大约是多少？

A. 1–2°C
B. 2–3°C
C. 3–4°C
D. 4°C 以上
```

提交后不立即只显示对错，而显示：

```text
你的选择：B
模型结果：+2.94°C
你与模型相差：0.06°C
```

### 6.2 原因卡

每个结果后面提供三层解释：

#### 第一层：一句话

> CO₂ 增加后，地球向外散热变慢，系统会积累更多能量。

#### 第二层：因果链

```text
CO₂ 上升 → 辐射强迫增加 → 海洋和地表吸热 → 全球温度上升
```

#### 第三层：技术细节

- 方程 ID。
- 输入变量。
- 输出变量。
- 参数。
- 数据来源。
- 模型状态类型。

### 6.3 复述卡

实验完成后要求用户完成一句话：

> “我观察到 ______，因为 ______，但这个结果不能说明 ______。”

示例：

> 我观察到 SSP5-8.5 的海平面继续上升，因为海洋热膨胀和冰冻圈响应具有滞后，但这个结果不能说明某个城市一定会发生风暴潮淹没。

这是教育闭环中最重要的输出之一。

### 6.4 概念卡库

第一批概念：

- 排放路径。
- 浓度路径。
- 辐射强迫。
- 两层海洋模型。
- 全球平均温度。
- 海平面四分量。
- 聚合箱。
- 诊断式估计。
- 模式缩放。
- 参数不确定性。
- 长期探索性外推。

每张概念卡包括：

- 一句话定义。
- 现实类比。
- 当前模型中的位置。
- 一个可操作实验。
- 一个容易误读的地方。

## 7. 游玩功能体系

### 7.1 任务卡结构

每张任务卡包含：

```text
任务标题
任务背景
你的目标
可以调整的变量
需要观察的指标
完成条件
结果解释
```

任务示例：

```text
任务：让 2100 年升温低于 2°C

目标：ΔT2100 < 2°C
可调：减排起始年、排放规模、甲烷路径、碳汇能力
观察：温度、CO₂、海平面、首超年份
完成后：比较你的路径和 SSP2-4.5
```

### 7.2 徽章体系

徽章不奖励灾难，而奖励理解和探索。

#### 理解徽章

- 看懂碳循环。
- 理解海洋滞后。
- 认识海平面四分量。
- 区分全球和局地结果。
- 理解诊断式结果。
- 理解参数不确定性。

#### 探索徽章

- 查看四个 SSP。
- 访问五个城市。
- 查看四个关键年份。
- 打开海平面分量图。
- 开启一次不确定性区间。
- 完成一次 A/B 对比。

#### 表达徽章

- 完成一句话复述。
- 分享一个带上下文的结果。
- 解释一个模型边界。
- 用两个指标说明情景差异。

### 7.3 进度系统

进度不做成竞争排行榜，而做成个人探索地图：

```text
已理解：3 / 10 个核心概念
已完成：4 / 12 个实验任务
已探索：5 / 20 个城市
已比较：2 / 4 个情景
已分享：1 个结果
```

用户可以看到“我还没有探索什么”，而不是只看到分数。

### 7.4 连续探索

每次实验完成后推荐下一步：

- 你刚刚比较了温度，接下来看看海平面四分量。
- 你刚刚查看了全球平均，接下来选择一个城市。
- 你刚刚改变了减排年份，接下来试试只改变海岸防护。
- 你刚刚看了确定性结果，接下来打开参数区间。

## 8. 传播功能体系

### 8.1 结果分享卡

分享卡必须包含：

- 情景。
- 年份。
- 城市/全球范围。
- 核心指标。
- 与基准的差异。
- 模型性质。
- 限制说明。
- 二维码或短链接。

示例：

```text
上海 · SSP2-4.5 · 2100

全球升温：+2.94°C
本地升温：+3.23°C
海平面：+0.74m
当前模型下：未判定为城市点级淹没

教育性情景估计 · 城市点级降尺度
打开链接继续探索 →
```

### 8.2 可复现 URL

统一使用现有 URL 状态机制：

```text
/?scenario=ssp585&year=2100&unc=1&exp=...
```

必须恢复：

- 情景。
- 年份。
- 不确定性开关。
- 实验参数。
- 当前城市或区域。
- 当前图层。
- 当前分析 tab。

### 8.3 A/B 对比分享

用户可以分享：

```text
我的路径 vs SSP2-4.5
2100 年温度差：-0.86°C
海平面差：-0.14m
首次超过 2°C：晚 21 年
```

### 8.4 我的城市分享

城市结果是最重要的传播入口之一。

用户输入或点选城市后生成：

- 2026 / 2050 / 2100 三个年份对比。
- 两个情景对比。
- 局地升温。
- 年均温。
- 降水。
- 群系。
- 高程来源。
- 淹没判定。

### 8.5 Embed 模式

支持嵌入：

```text
/embed?scenario=ssp245&year=2100&city=Shanghai
```

Embed 默认只保留：

- 地球/地图。
- 年份。
- 三个核心指标。
- 简洁图层控制。
- 返回完整模拟页面的链接。

### 8.6 社交分享文案

系统自动生成包含上下文的文字：

> 我比较了 SSP2-4.5 和 SSP5-8.5。到 2100 年，两条路径的全球平均升温相差约 2.2°C，海平面相差约 0.27m。未来地球引擎允许继续拖动时间轴查看城市变化。

## 9. 城市体验设计

### 9.1 城市入口

在首页和 Overview 设置明显入口：

> **看看你的城市在 2100 年会怎样**

提供：

- 搜索城市。
- 热门城市。
- 最近访问城市。
- 地图点选。

### 9.2 城市结果卡

城市卡包含：

| 区块 | 内容 |
|---|---|
| 当前状态 | 城市、高程、人口、数据来源 |
| 温度 | 全球 ΔT、本地 ΔT、年均温 |
| 水分 | 基准降水、未来降水 |
| 生态 | 群系分类变化 |
| 海岸 | 高程、SLR、城市点级淹没判定 |
| 解释 | 结果来自什么模型层级 |
| 边界 | 不包含沉降、潮汐、风暴潮等 |

### 9.3 城市任务

- 找到 2100 年最早接近海平面阈值的城市。
- 比较两个城市的局地升温。
- 找到全球升温相同但局地升温不同的城市。
- 比较内陆城市和沿海城市的风险链。
- 解释为什么某个城市没有被判定淹没，但仍然可能存在其他风险。

## 10. 课堂与教育场景

### 10.1 课堂模式

课堂模式适合投屏：

- 隐藏复杂规格表。
- 大字号显示问题和选项。
- 允许教师先让学生投票。
- 统一运行模拟。
- 显示全班预测与模型结果差异。
- 最后显示讨论问题。

### 10.2 课堂任务包

第一批建议提供四个任务：

#### 任务 A：四种未来

目标：比较四个 SSP 在 2100 年的温度、CO₂ 和海平面。

#### 任务 B：减排时间

目标：比较 2035、2050、2070 开始减排的差异。

#### 任务 C：海平面分解

目标：判断热膨胀、冰川和冰盖的贡献差异。

#### 任务 D：城市与全球

目标：比较全球平均升温与三个城市的局地升温。

### 10.3 教师输出

- 任务链接。
- 课堂投屏链接。
- 结果 CSV。
- 任务完成情况。
- 学生复述答案。
- 讨论问题和模型边界。

### 11.3 内容事实源

任务和解释可以使用新的 `overview-content.yaml` 或 `missions.yaml`，但涉及模型事实的字段必须能够追溯到：

- `variables.yaml`。
- `equations.yaml`。
- `scenarios.yaml`。
- `datasets.yaml`。
- 引擎 `SimResult`。
- 参数指纹和 manifest hash。

## 12. 科学完整性守则

### 12.1 不做虚假精确

不要用：

- “你所在城市一定会在 2073 年被淹没”。
- “模型证明了某项政策一定有效”。
- 没有单位和年份的单一灾难数字。

推荐：

- “在当前城市点级判定下”。
- “在 SSP2-4.5 情景下”。
- “参数区间显示为”。
- “2100 年以后属于探索性外推”。

### 12.2 不把影响函数说成观测

水资源、农业、经济损害和生态指标必须标注：

- 教育性估计。
- 使用的简化公式。
- 适用范围。
- 可能遗漏的变量。

### 12.3 不把颜色当结论

所有图层必须同时有：

- 图例。
- 单位。
- 当前年份。
- 当前情景。
- 数据来源。
- 模型层级。

## 15. 验收标准

### 教育验收

- EDU-01：用户能说出情景、模型输出和城市结果之间的关系。
- EDU-02：用户完成一次预测后能看到预测与结果差异。
- EDU-03：用户能解释至少一个结果的原因。
- EDU-04：用户能区分动态耦合、诊断估计和模式缩放。
- EDU-05：用户能说出一个模型限制。

### 游玩验收

- PLAY-01：第一次任务 3–5 分钟内完成。
- PLAY-02：完成一个任务后有明确下一步推荐。
- PLAY-03：用户可以在不重新学习全部界面的情况下重复运行新的实验。
- PLAY-04：挑战目标可以被自动判定。
- PLAY-05：徽章和进度奖励探索与理解，不奖励灾难极端化。

### 传播验收

- SHARE-01：分享链接可恢复同一情景、年份和实验参数。
- SHARE-02：分享卡包含指标、年份、情景、模型性质和限制说明。
- SHARE-03：城市结果可生成独立分享内容。
- SHARE-04：分享对象打开后可以继续操作，而不是只能看截图。
- SHARE-05：PNG、CSV 和页面数值一致。

### 性能与工程验收

- PERF-01：普通情景切换不阻塞主线程。
- PERF-02：蒙特卡洛走 Worker。
- PERF-03：任务结果与 `SimResult` 同一事实源。
- PERF-04：任务内容不复制方程、参数和数据源事实。
- PERF-05：所有分享结果带 modelVersion、paramsFingerprint 和 dataManifestHash。

## 16. 成功指标

不要只看停留时长，应关注用户是否完成了可理解的实验。

| 指标 | 含义 |
|---|---|
| 首次完成任务率 | 用户是否真正完成一次预测—模拟—解释 |
| 首次情景切换率 | 用户是否主动尝试第二条路径 |
| 首次城市查询率 | 全球结果是否成功落到个人相关场景 |
| A/B 对比完成率 | 用户是否理解“差异”而不是只看一个结果 |
| 解释面板打开率 | 用户是否愿意理解为什么 |
| 复述完成率 | 用户是否形成自己的语言表达 |
| 分享链接打开率 | 分享是否产生继续探索 |
| 分享后再次操作率 | 分享不是终点，而是新的入口 |
| 任务复玩率 | 产品是否有真正的游玩循环 |
| 模型边界回答正确率 | 用户是否形成科学限制意识 |
