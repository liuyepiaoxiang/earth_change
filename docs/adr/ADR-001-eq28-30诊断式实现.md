# ADR-001：eq_28–30 采用诊断式实现，不耦合进 v0 状态机

| 项目 | 内容 |
|---|---|
| 状态 | accepted |
| 日期 | 2026-10-11 |
| 决策人 | earth-change（单人项目，AI 起草） |
| 背景 | V1-02（2D 模式场：海冰范围/冰-反照率）要求实现 eq_28–30。三条方程在 YAML 中标记 impl: v1（第 6/7 组：海冰面积、地表反照率、冰-反照率反馈回路 L2），而一致性测试强制「已注册 ⇔ impl: v0」。若把海冰-反照率反馈耦合进 v0 求解器 RHS，将改变模拟轨迹，触发 G1–G5 校准失效与重新校准，v0 交付的定量对标即被推翻 |

## 备选方案

| 方案 | 说明 | 评估 |
|---|---|---|
| A. 耦合式 | 海冰-反照率反馈接入 RHS（α 变化 → F 反馈项），重新校准 | ❌ 推翻 G1–G5 已验收状态；v0 交付口径失效；引入新的校准风险 |
| B. 诊断式（本决策） | 方程实现为**纯函数并注册**，输入取自模拟输出（如 ΔT），由 UI 直接调用展示；不进入 solver RHS，不改变状态向量 | ✅ G1–G5 逐位不变；先例：eq_49–53 降尺度同为注册诊断式（UI 直接调用） |
| C. 不实现 | 保持 impl: v1 占位 | ❌ V1-02 要求实现、注册与测试；占位无交付 |

## 决策

**方案 B（诊断式）**，具体口径：

1. `equations.yaml` 中 eq_28/29/30 的 `impl` 由 v1 改为 **v0**（本仓 impl 语义 =「已实现并注册」，v0 层从 21 条扩到 24 条，其中耦合式 21 + 诊断式 3），`notes` 标注「诊断式，不接入 RHS」。
2. 实现放 `packages/engine/src/equations/seaice.ts`，三个纯函数：
   - `seaIceArea(dTs)` — eq_28：logistic 经验曲线（A₀=9.5、T₅₀=2.3、k=0.88 M km²，锚点 1850≈8.9 / +1.2°C≈7.4 / +4°C≈1.2 / 无冰 ≈0），YAML 原式 dA/dt=f(To,Ta,A) 为速率式，诊断式取**均衡面积**而非速率，避免接入积分器；
   - `surfaceAlbedo(areaIce, area0)` — eq_29：α = α0 − kᵢ·ΔA（α0=0.30，kᵢ=0.03 /M km²，全冰损失 ≈ −0.28 对应冰面 0.6 → 海面 0.06 的量级）；雪被/植被项（Asnow/V）依赖 v1/v2 变量，本轮缺省为 0 并在函数注释标明；
   - `iceAlbedoFeedback(deltaAlpha, lambda)` — eq_30：反馈的辐射当量 ΔF = −(S₀/4)·(1−c)·Δα（S₀=1361 W/m²，云量 c=0.6），返回 W/m²（回路 L2 的增益诊断）。
3. 三函数注册进 `registry.ts`（一致性测试自动覆盖）；**不修改** `solver.ts` 的 RHS 与状态向量。
4. UI 消费：MetricsBar 增加海冰面积显示（`seaIceArea(ΔT)`），与 eq_49–53 的消费方式一致。

## 影响

| 维度 | 影响 |
|---|---|
| G1–G5 | 零影响（runSim 路径未变，golden 必须保持全绿——CI 验证） |
| 规格 | SPEC §4.4 回填注记：v0 = 24 条（21 耦合 + 3 诊断）；YAML 是唯一事实源 |
| 测试 | 新增 seaice.test.ts（锚点/单调/线性/符号）；一致性测试自动覆盖注册 |
| UI | MetricsBar 增海冰面积 |
| v2 | 若 v2 植被/积雪落地，eq_29 的 Asnow/V 项与 eq_30 的耦合升级届时再评估（将产生新 ADR） |
