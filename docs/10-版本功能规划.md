# 未来地球引擎版本功能规划

> 版本：1.0  
> 规划日期：2026-10-16  
> 适用范围：模型、数据、引擎、Web 产品、测试、发布与传播  
> 当前基线：v0.1 可运行原型，v1/v2/v3 的部分方程批次已落地  
> 文档性质：版本规划与范围控制，不替代 `docs/superpowers/specs/` 中的方程规格

---

## 1. 规划目标

未来地球引擎不以“方程数量最多”为版本目标，而以以下四个结果为发布标准：

1. **结果可信**：用户知道哪些是动态耦合预测、哪些是诊断估计、哪些是外生情景输入。
2. **过程可解释**：用户能够看到温度、碳循环、海平面、冰冻圈和影响之间的因果链。
3. **交互可参与**：用户可以创建、比较、保存和分享自己的未来情景。
4. **范围可控制**：每次增加模型复杂度时，都有数据、校准、验收门和性能预算，不把教育性箱式模型误包装成高分辨率地球系统模型。

本规划将版本分成三条并行路线：

| 路线 | 解决的问题 | 主要产物 |
|---|---|---|
| 模型路线 | 地球状态能否更完整、更自洽地演化 | 方程、状态量、校准、数据、验收门 |
| 产品路线 | 用户能否理解和操作预测结果 | 图表、地图、实验室、城市面板、可访问性 |
| 传播路线 | 结果能否复现、分享和被继续探索 | URL 状态、分享卡、导出、嵌入、开放 API |

## 2. 当前基线与版本判定

### 2.1 当前已经具备的能力

当前版本已经形成以下可运行闭环：

- 1850–2024 历史段与 2025–2500 情景段串联。
- SSP1-2.6、SSP2-4.5、SSP3-7.0、SSP5-8.5 四个情景。
- CO₂、CH₄、N₂O、其他辐射强迫、两层海洋能量平衡。
- 全球平均温度、深海温度和海平面四分量。
- 生物量、土壤水分、火灾异常通量、冻土碳箱。
- 纬度带温度缩放、城市温度/降水/群系/淹没查询。
- 海冰面积和冰反照率诊断。
- 确定性蒙特卡洛区间、Web Worker、3D 地球、时间轴和图层控制。
- `/api/simulate`、静态数据打包、manifest 校验、CI、Playwright E2E。

### 2.2 当前能力的真实层级

“53 条方程全部有实现”不等于“53 条方程全部形成完整动态耦合”。当前应按以下层级对外表述：

| 层级 | 当前状态 | 说明 |
|---|---|---|
| 全球核心气候链 | 已完成 | 碳循环、辐射强迫、两层能量平衡、海平面分解进入主求解器 |
| 生物圈/冻土聚合箱 | 已完成简化版 | 有动态状态和反馈，但仍是全球聚合箱，不是区域生态模型 |
| 水循环 | 已完成诊断/聚合箱版 | 有降水、蒸发、径流、土壤水函数，区域水循环尚未耦合 |
| 海冰/反照率 | 已完成诊断版 | 海冰由温度诊断，反照率反馈未进入主 RHS |
| 城市降尺度 | 已完成 | 纬度带模式缩放和城市点级查询 |
| 全局空间场 | 未完成 | 目前不是区域温度、降水、植被和水文的时间积分网格 |
| 地貌演化 | 已完成标量诊断版 | 侵蚀、沉积、海岸函数已实现，格点时间演化未完成 |
| 影响与适应 | 未完成 | 暴露人口、洪水频率、水资源、农业、经济损害尚未形成完整模块 |

### 2.3 当前必须先修正的治理问题

在进入下一版本前，必须处理以下一致性问题：

1. 统一 `equations.yaml`、`variables.yaml`、`datasets.yaml` 的 `impl` 语义，区分“已注册”“已耦合”“诊断式”“规划中”。
2. 修正规格数据源路径与实际 manifest 的差异，例如 `cities_top2000.csv` 与当前 `cities_top500.csv`、`dem_0.1deg.png` 与当前 5 角分高程图。
3. 明确情景段 CO₂ 是浓度驱动还是排放驱动，并在 `SimResult` 元数据中标记。
4. 为 2100 年以后增加“探索性外推”标识，避免用户把 2200–2500 年结果理解成同等置信度的科学预测。
5. 统一 `schemaVersion`、不确定性输出和模型版本号，保证 API、Worker、客户端和文档使用同一契约。

## 3. 版本总览

| 版本 | 主题 | 状态/目标 | 核心用户价值 |
|---|---|---|---|
| v0.1 | 可运行地球原型 | 当前基线 | 能运行情景、拖动时间轴、观察地球和城市 |
| v0.2 | 可信度与可解释性 | **已交付（2026-10-16）** | 知道结果如何产生、哪里可靠、哪里是简化 |
| v0.3 | 情景实验室与分享 | **已交付（2026-10-17）** | 用户可以改参数、比较方案、保存并分享结果 |
| v1.0 | 区域化气候场 | **已交付（2026-10-17）** | 从全球/城市点扩展到区域温度、降水和水文 |
| v1.5 | 反馈侧升级 | **已交付（2026-10-17）** | 海冰、碳汇、水循环和生态反馈更加自洽 |
| v2.0 | 影响与适应 | **已交付（2026-10-17）** | 看到暴露人口、水资源、农业和城市风险 |
| v3.0 | 海岸与地貌演化 | **已交付（2026-10-17）** | 观察海岸线、侵蚀、沉积和地形变化 |
| v4.0 | 深度不确定性与临界点 | **已交付（2026-10-17）** | 区分参数、情景、结构和临界点不确定性 |

版本号规则：

- `v0.x`：保证当前教育性原型可用，优先补可信度、解释和用户参与。
- `v1.x`：引入真正的区域空间状态，但仍保持浏览器可运行和教育性定位。
- `v2.x`：从气候状态扩展到人类和生态影响，不把影响指标冒充为气候观测量。
- `v3.x`：实现地表和海岸的时间演化，增加空间守恒和性能门。
- `v4.x`：处理深度不确定性、临界点和替代模型，不以单一确定曲线作为唯一答案。

## 4. v0.1 已交付版本

### 4.1 版本定位

v0.1 是“全球气候核心 + 3D 地球展示”的可运行原型，不承诺完整地球系统耦合。

### 4.2 已交付范围

- 规格层：YAML、Zod 校验、生成类型、方程注册一致性。
- 数据层：历史数据、情景数据、静态空间数据、manifest 和生成 bundle。
- 引擎层：RK4、NaN 守卫、参数校准、G1–G5 黄金测试、CLI。
- Web 层：3D 地球、温度层、城市点、淹没层、降水层、时间轴、情景切换。
- API 层：参数校验、版本化 `SimResult`、确定性缓存。
- 工程层：CI、组件测试、E2E、Worker 回退路径。

### 4.3 v0.1 的明确边界

- 未来 CO₂ 情景段以外生浓度路径为主。
- 海冰是温度诊断量，不是动力学海冰模型。
- 降水是标量缩放与静态底图叠加，不是区域水循环预测。
- 淹没是城市点级判定与 DEM 视觉近似，不是完整沿海洪水模型。
- 地貌方程是标量诊断，不是格点时间积分。
- 2500 年结果是长期探索性外推。

### 4.4 v0.1 验收状态

- [x] `pnpm test` 等价命令通过。
- [x] `pnpm typecheck` 通过。
- [x] `pnpm --filter web build` 通过。
- [x] G1 历史温度。
- [x] G2 历史 CO₂。
- [x] G3 历史海平面。
- [x] G4 2100 年四情景温度区间。
- [x] G5 数值健全性、确定性和历史碳守恒。
- [x] G6 生物圈/冻土箱基本约束。
- [x] Playwright API、交互、图层和视觉测试。

## 5. v0.2：可信度与可解释性

### 5.1 版本目标

把当前“能跑出结果”升级为“用户知道结果是什么、为什么、可信到什么程度”。

这是下一版本的最高优先级，不应先继续堆叠更多方程。

## 6. v0.3：情景实验室与分享

### 6.1 版本目标

让用户不只是选择四个 SSP，而是可以提出一个问题、改变几个条件、比较结果并分享实验。

### 6.2 情景实验室

第一版只开放经过参数范围约束的教育性控制，不允许直接修改内部校准参数。

| 控制项 | 允许形式 | 影响对象 |
|---|---|---|
| 排放强度 | 相对 SSP 路径的 0.5–1.5 倍 | 排放、浓度、温度 |
| 减排起始年 | 2025–2100 | 排放曲线 |
| 净零年份 | 2030–2200 | 长期排放 |
| 甲烷路径 | 低/中/高三档 | 非 CO₂ 强迫 |
| 土地利用排放 | 低/基准/高三档 | 碳循环、生物量 |
| 碳汇能力 | 保守/基准/增强 | CO₂ 和温度 |
| 海岸防护 | 不防护/固定高程/适应情景 | 城市暴露结果 |

### 6.3 产品交互

- 情景编辑器与当前 SSP 对比。
- 左右或上下双栏比较两个情景。
- 显示“相比基准少排放多少、少升温多少、少升海平面多少”。
- 显示首次超过 1.5°C、2°C、3°C 的年份。
- 显示最早受影响城市和受影响城市数量。
- 支持保存最近 3–5 个本地实验。
- 支持实验名称、备注和恢复默认值。
- 时间轴增加关键年份标记：2030、2050、2100、2200、2500。

### 6.4 分享与导出

建议使用 URL 作为可复现状态：

```text
/?scenario=ssp585&year=2100&city=lagos&layers=temperature,flood&uncertainty=1
```

交付内容：

- 复制实验链接。
- 导出当前视图 PNG。
- 导出当前情景 CSV。
- 生成包含情景、年份、温度、海平面和城市状态的分享卡片。
- `/embed` 嵌入模式，隐藏编辑器但保留时间轴和指标。
- API 返回 `canonicalUrl` 和实验摘要。

### 6.5 v0.3 验收门

- SCE-01：同一 URL 在不同浏览器恢复同一状态。
- SCE-02：相同情景、参数和 seed 得到逐位一致结果。
- SCE-03：两个情景可以同时显示并对齐年份。
- SCE-04：导出的 CSV 与页面指标一致。
- SCE-05：分享卡片不依赖浏览器本地状态。
- PERF-01：普通情景切换不阻塞主线程。
- PERF-02：MC 计算始终走 Worker，失败时有明确回退提示。

### 6.6 v0.3 明确不做

- 不允许用户直接编辑 `lambda`、`gamma_ocean` 等校准参数。
- 不支持多人协作和云端账户。
- 不把自定义参数实验称为官方 SSP 情景。

## 7. v1.0：区域化气候场

### 7.1 版本目标

从“全球平均量 + 城市点查询”升级为可浏览、可采样、可验证的区域化气候场。

### 7.2 模型范围

第一阶段采用低分辨率规则化网格，不追求大气动力学：

- 区域温度场：全球温度与纬度放大、陆海差异、极地放大。
- 区域降水场：基准降水、温度响应、纬度和陆海修正。
- 区域蒸发和土壤水分：网格化诊断。
- 区域径流：水量平衡和容量限制。
- 区域积雪：温度阈值和度日融化。

## 8. v1.5：反馈侧升级

### 8.1 版本目标

将当前诊断式水循环、海冰和生物圈扩展为有限的动态反馈，同时保持可校准、可解释和可回滚。

### 8.2 反馈分期

#### 8.2.1 海冰—反照率反馈

- 海冰面积从单一全球值扩展为高纬度网格。
- 雪面、裸地、海水和海冰反照率分开。
- 反照率变化进入辐射强迫。
- 增加冰—反照率反馈强度和饱和边界。

#### 8.2.2 碳循环增强

- 植被 NPP、异养呼吸、土壤碳分开记账。
- 火灾异常通量和植被恢复时间尺度分开。
- 冻土碳区分 CO₂ 和 CH₄ 释放份额。
- 陆地碳汇对温度、水分和 CO₂ 的响应可诊断。

#### 8.2.3 水循环反馈

- 植被—降水反馈只在有数据支持的区域启用。
- 土壤水和径流进入植被和火灾模块。
- 加入干旱持续时间，而非只使用瞬时水分亏缺。

### 8.3 核心约束

每个新增反馈必须遵守：

1. 先写 ADR，明确异常量还是绝对量。
2. 先定义输入、输出、单位和守恒关系。
3. 先添加关闭反馈的基线测试。
4. 开启反馈后重新校准，不得放宽 G1–G6。
5. 对参数不确定性使用固定先验，不能用 MC 代替校准。
6. 每个反馈必须可以在 UI 中解释其方向和大小。

### 8.4 验收门

- G15：海冰—反照率关闭时结果回到原基线。
- G16：海冰、反照率和总强迫分量闭合。
- G17：碳库、碳通量和 CO₂ 增量守恒。
- G18：水量守恒和径流非负。
- G19：高温/干旱下火灾反馈单调但不发散。
- G20：冻土库不穿底，释放速率有上限。
- G21：反馈关闭、开启和参数扰动均可复现。

## 9. v2.0：影响与适应

## 14. 版本发布流程

每个版本按以下顺序推进：

1. 明确版本问题和非目标。
2. 从本文件提取任务，写入 `docs/03-开发任务清单.md`。
3. 更新规格 YAML 和 ADR。
4. 先补测试和验收门。
5. 实现数据管道和生成物。
6. 实现引擎纯函数与主求解器接入。
7. 校准并检查历史、情景和物理门。
8. 实现 Web 交互和解释层。
9. 运行单测、类型检查、构建和 E2E。
10. 生成版本说明、数据版本、参数指纹和已知限制。
11. 发布候选版本。
12. 进行浏览器冒烟和分享链接回归。

每个任务应保持可独立回滚。模型方程、参数、数据、API 和 UI 不应在同一个不可拆分提交中混合变更，除非它们属于同一个完整契约变更。

## 16. 总结

未来地球引擎下一阶段的核心不是继续把“已注册的方程”增加到更多，而是把当前能力变成一个用户能够信任、理解、操作和传播的产品。

建议的产品主线是：

```text
可运行
  → 可验证
  → 可解释
  → 可参与
  → 可分享
  → 区域化
  → 影响化
  → 深度不确定性
```

建议的模型表述保持克制：

> 当前系统是全球聚合箱气候情景模拟器，具备城市级降尺度和多项诊断模块；后续版本逐步扩展到区域网格、影响侧和深度不确定性，但每一步都必须保留守恒、校准、可解释和可复现能力。
